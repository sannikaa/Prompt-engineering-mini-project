# Code Evaluation Rubric

Each code submission is evaluated on four dimensions.
Each dimension receives a score from 0 to 10.

## 1. Correctness
- 0-2: Completely incorrect or does not address the task.
- 3-4: Major logical errors; works only in limited cases.
- 5-6: Partially correct; fails some important edge cases.
- 7-8: Mostly correct; handles normal cases and most edge cases.
- 9-10: Correct implementation; handles specified cases and edge cases.

## 2. Security
- 0-2: Contains serious security risks.
- 3-4: Multiple significant unsafe practices.
- 5-6: Some security concerns or insufficient input handling.
- 7-8: Generally safe with minor concerns.
- 9-10: No evident security concerns for the given task.

## 3. Readability
- 0-2: Extremely difficult to understand.
- 3-4: Poor naming, structure, or formatting.
- 5-6: Understandable but has clarity issues.
- 7-8: Clear structure and reasonable naming.
- 9-10: Very clear, consistent, and maintainable.

## 4. Efficiency
- 0-2: Extremely inefficient approach.
- 3-4: Major unnecessary computational overhead.
- 5-6: Acceptable but has avoidable inefficiencies.
- 7-8: Efficient for expected inputs.
- 9-10: Appropriate and well-optimized for the problem.

## Evaluation Rules
- Evaluate only the submitted code and given problem.
- Do not invent bugs.
- Do not reward longer code merely because it is longer.
- Consider edge cases.
- Explain every score with evidence.
- State limitations when information is insufficient.

## Overall Score
Calculate the arithmetic mean of the four dimension scores.
